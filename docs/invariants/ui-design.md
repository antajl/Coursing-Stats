## Invariants & Architectural Rules

### Old Money Aesthetic Principles & Zero Emoji Standard

Интерфейс проекта CoursingStats выдержан в строгой эстетике **Old Money / Quiet Luxury**:
1. **Цветовая палитра:** Базовые молочные и песочные фоны (`sand-50` / `#FAF8F5`, `sand-100` / `#F5F0E8`), глубокий угольный текст (`charcoal-900` / `#221F1F`, `charcoal-700` / `#4A4238`), благородные верблюжьи акценты (`camel-500` / `#C89D66`, `camel-600` / `#B28247`). Запрещены кислотные или холодные неоновые оттенки (purple, violet, cyan glow).
2. **Строго ZERO эмодзи:** Никаких эмодзи в интерфейсе (ни в коде, ни в заголовках, ни в кнопках, ни в табах, ни в бейджах, ни в сообщениях об ошибках). Все визуальные акценты создаются исключительно иконками Lucide или типографикой.
3. **WCAG Контрастность:** Подписи метрик карточек и вторичный текст строго темнее `#685E53` (контраст $\ge 4.5:1$ к фону `sand-100`). Текст активных плашек имеет глубокий контраст `#201202`.
4. **Интерактивные зоны (Touch Targets):** Любой интерактивный элемент на мобильных устройствах обязан иметь физическую зону нажатия $\ge 44 \times 44\text{px}$ (через `min-h-[44px]` или `before:absolute before:-inset-2`).
5. **Чистая консоль (Zero Console Noise):** При открытии страниц в браузере не должно быть предупреждений React, ошибок гидратации или мусорных `console.log`.

### Physical Glassmorphism, Shadow Clearance & Corner Radii Hierarchy

1. **Иерархия скруглений:**
   - **Одиночные интерактивные элементы (кнопки, плашки фильтров, пилюли поиска, чипы):** Строго капсульные `rounded-full` (`border-radius: 9999px`) в стиле Physical Floating Glass.
   - **Внешние карточки и панели (Hero, колонки, консоли, модалки):** Строго `rounded-2xl` (16px).
   - **Внутренние вложенные блоки:** Строго `rounded-xl` (12px) или `rounded-lg` (8px). Запрещена обратная иерархия.
2. **Стиль Physical Glass:** Активные плашки (`.cs-glass-pill-active`) и неактивные плашки (`.cs-glass-pill`) оформляются кристальным янтарным телом стекла с тонким кантом `border: 1px solid rgba(195, 168, 128, 0.75)` и мягкой рассеянной многослойной тенью:
   - Активные: `inset 0 1.5px 1px 0 #fff, inset 0 0 0 1px rgba(255, 240, 200, 0.85), 0 3px 14px 0 rgba(120, 80, 30, 0.12), 0 1px 4px 0 rgba(70, 45, 15, 0.05)`.
   - Неактивные: `inset 0 1px 1px 0 rgba(255, 255, 255, 0.95), inset 0 0 0 1px rgba(230, 215, 195, 0.65), 0 2px 8px 0 rgba(100, 80, 60, 0.04)`.
3. **Типографика плашек:** И активные, и неактивные плашки оформляются строго `font-semibold` (`font-weight: 600`). Запрещен `font-bold` для активных плашек.
4. **Shadow Clearance:** Контейнеры карточек с тенями строго запрещено обрезать свойствами `contain: paint` или жестким `overflow: hidden`, срезающими мягкую тень в прямой угол. Контейнер обязан сохранять прозрачный зазор безопасности $\ge 4\text{px}$ (`p-1` или `px-1 py-1.5`).

### QuickBreedBar Edge-to-Edge Alignment, FLIP Motion & Stability

1. **Edge-to-Edge выравнивание:** Панель фильтрации `QuickBreedBar` является самой правой частью тулбара и растягивается на 100% ширины контейнера (`w-full min-w-0`), крайняя правая кнопка выравнивается строго по правому краю контента.
2. **Состояние одиночной породы (Single-Breed State):** При выборе любой породы все остальные плашки скрываются. В строке отображается ровно один аккуратный компактный бейдж выбранной породы в стиле активного кристального стекла со встроенным крестиком сброса `(x)`. Отдельная кнопка «Сбросить фильтр» упразднена как визуальный мусор.
3. **FLIP-анимация:** Переход между полным набором плашек и одиночным состоянием осуществляется через нативные CSS-переходы (`transform`, `opacity`, `scale`), исключая резкие скачки верстки.
4. **Стабильность при загрузке:** Базовые породы-кандидаты (`SHOW_CANDIDATE_BREEDS`, `CANDIDATE_BREEDS`) запрещено отсекать при частичной или асинхронной загрузке данных (`page0` рейтинга выставок). Строгая фильтрация включается строго после полного завершения фоновой загрузки.

### Mobile 120 FPS Touch Swipe, Safari Viewport & Lighthouse Accessibility Standard

1. **Единый свайп-хук:** Для мобильной свайп-навигации между вкладками и колонками (`BreedHubColumns`, `DogDisciplinesMobileView`, `TopDogsColumns`) используется строго единый хук `useHorizontalSwipe` (`frontend/src/hooks/useHorizontalSwipe.ts`), гарантирующий одинаковую кинематику жеста, сопротивление границ и пороги переключения.
2. **In-Card Swipe:** Свайп происходит строго внутри монолитного контейнера карточки, язычки вкладок интегрируются в верхний кант карточки.
3. **Аппаратное ускорение 120 FPS:** Перемещение управляется через GPU (`translate3d(calc(...), 0, 0)`, `will-change: transform`), без вызова ререндеров React во время движения пальца. На граничных слайдах применяется степенное демпфирование (`deltaX * 0.25`).
4. **Защита от Scroll Container Trap:** На мобильных устройствах во избежание паразитных скролл-ловушек запрещено сочетание `overflow-x-hidden` с отрицательными марджинами (`-mx-4`), срезающими интерактивные кнопки при вертикальном скролле.
5. **iOS Safari:** Во всех модальных окнах, оверлеях (`fixed inset-0`) и шторках для кликабельных бэкдропов строго используются теги `<button>` с `aria-label="Закрыть"` вместо `<div>`. Мобильные оверлеи используют `100dvh` вместо `100vh`. Поля ввода имеют `text-base sm:text-sm` для предотвращения нежелательного авто-зума в Safari.
6. **Lighthouse 100/100:** Строго соблюдается непрерывная иерархия заголовков (`h1` -> `h2` -> `h3`) без пропусков уровней.

### Two-Column Dashboard Horizon Alignment & Home Executive Consoles

1. **Горизонт двухколоночных дашбордов:** В двухколоночных макетах аналитики и главной страницы верхние границы левого и правого контентных блоков обязаны начинаться на строго одном горизонтальном уровне (`border-t` на единой оси).
2. **Монолитные консоли главной:** На десктопе ($\ge 768px$) дашборд лидеров сезона и базы данных оформляется в виде двух симметричных консолей равной высоты (316px / 336px при $\ge 1280px$). Промежуточные служебные строки-подзаголовки и нижние футеры с дублирующими ссылками упразднены.
3. **Сохранение табов без сдвигов (Zero Layout Thrashing):** В табированных экранах вкладки сохраняются в DOM при переключении (`visitedTabs` со стилями `hidden` / `.animate-fade-in`), предотвращая повторный сетевой фетч и мигание скелетонов.

### Breed Hub Multi-Discipline Architecture, Hero & Swipe Navigation

1. **Динамические метрики:** В хабах пород (`/breeds/:slug/`) запрещены статические синтетические заглушки («Пиковая скорость: до 60 км/ч», «Дистанция 700–1000 м»). Все показатели (собак в базе, забегов, золотых наград, рекордов скорости) рассчитываются динамически из реальных протоколов.
2. **Интегрированная шапка:** Русское название (`nameRu`), латынь (`nameLat`), стандарт (`FCI {fci}`) и охват сезонов объединяются в единую строку заголовка.
3. **Канонические международные слаги:** Основной породный хаб использует международный канонический слаг на латинице (`dachshund`, `whippet`), а специализированные наименования и синонимы разновидностей прозрачно разрешаются в него.
4. **Мобильная навигация:** На смартфонах переключение дисциплин вынесено в шапку карточки в виде бейдж-табов, синхронизированных со свайпом `useHorizontalSwipe`.
5. **Модульная структура:** Компонент `BreedHubColumns` декомпозирован на изолированные субмодули (`useBreedHubSwipe.ts`, `BreedDisciplineColumn.tsx`) объемом <250 строк.

### Breeds Catalog 50/50 Dual Bar, FCI Groups & Scroll Restoration

1. **Симметричный тулбар 50/50:** В каталоге пород (`/breeds/`) тулбар десктопа разделен на две равные половины: левая колонка отдана под поиск по породе (`w-full`), правая — под фильтр групп FCI с кнопкой быстрого сброса.
2. **Числовая сортировка групп FCI:** Выпадающий список групп FCI сортируется строго по возрастанию официального римского/арабского номера группы (1, 2, 3 ... 10, затем Вне классификации FCI), а не по алфавиту названий.
3. **Восстановление скролла (Zero-Blank Reveal):** При возврате из карточки породы или смене фильтра позиция скролла восстанавливается мгновенно до монтирования тяжелых DOM-узлов, исключая эффект белого экрана.

### Guide 4-Tab Architecture, Smart Search & Topics Marquee

1. **4 канонические вкладки:** В справочнике (`/guide`) строго зафиксированы 4 вкладки: 1) «Соревнования» (`titles`: курсинг/бега, регламенты, 3 уровня титулов, 5 критериев и анатомия протокола); 2) «Выставки» (`shows`: 10 уровней ринга РКФ, CACIB/CAC, BIS/BIG); 3) «Донино» (`donino`: замеры скорости, чемпионаты, регламент); 4) «Рейтинг CS» (`points`: математическая модель очков CS-v2, олимпийский каскад).
2. **Интеллектуальный поиск в шапке:** Поиск устойчив к опечаткам (Damerau-Levenshtein $\le 2$), поддерживает русскую морфологию и авто-конвертацию раскладки клавиатуры (`ghjnjrjk` -> `протокол`).
3. **Бегущая строка частых тем (`GuideTopicsTicker`):** Быстрые чипы частых тем оформляются строго в одну строку без переносов через плавную бесконечную анимацию. Используются исключительно естественные пользовательские фразы («Как считаются очки CS?», «Что такое CACL?») без технических тегов.
4. **Чистый запуск:** В гиде запрещены лишние hero-баннеры над табами: страница сразу открывает рабочие вкладки.

### Dog Silhouette 2D Vector Generation & Optical Fit Standard

1. **Стандарт 2D-вектора силуэтов:** Все силуэты пород собак (для шапок `/dog/:id`, карточек выставок и витрин) генерируются строго по эталонному стандарту:
   - Все четыре лапы заземлены на базовой линии горизонта ($y = 170.0$).
   - Строгий боковой профиль (side view profile), четкий породный силуэт без наклонов в 3/4.
   - Чистый замкнутый векторный контур без паразитных внутренних пикселей.
2. **Оптическая нормализация:** Запрещено использовать линейное масштабирование 1:1 по высоте в холке (при котором миниатюрные породы сжимаются в нечитаемые точки, а гиганты вылезают за границы). Применяется суб-линейное масштабирование со сдвигом центра масс в нижнюю треть.
3. **Мульти-контурная векторизация:** При векторизации пород с прорезями между лапами контуры объединяются в корневой `<g fill="currentColor">`, сохраняя правильный рендеринг при смене темы.

### Component Decomposition, Toolbar Architecture & Plumbing Standard

1. **Лимит размера модулей:** Все интерактивные компоненты кодовой базы, хуки и скрипты обязаны сохранять модульную архитектуру ($\le 400$ строк). Крупные узлы (>500 строк) декомпозируются на специализированные субмодули (<100–250 строк).
2. **Тулбары страниц:** Сложные фильтры (`Judges`, `ShowJudges`, `EventResults`, `ShowRanking`) изолируются в отдельные компоненты в поддиректориях `components/`.
3. **Явный проп-пламбинг:** В тулбарах пропсы поиска (`dogIndex`, `onSelect`, `activeFilters`) явно типизируются в интерфейсе и пробрасываются в дочерние поисковые селекторы без скрытых глобальных состояний.
4. **Недублирование счетчиков:** В тулбарах запрещено выводить повторяющиеся счетчики событий («28 · отфильтровано: 28 · с результатом: 28»). Отображается ровно одно лаконичное итоговое число.

### Canonical Season Routing, URL Paths & Navigation Subtab Persistence

1. **Канонические пути со сквозным сезоном:** Маршрутизация в разделах соревнований (`/competitions/`), выставок (`/shows/`) и рекордов Донино (`/speed-records/`) использует строгие канонические пути с годом в URL (`/{section}/{tab}/{year}/`, например `/competitions/ranking/2026/`).
2. **Сезон по умолчанию:** Клик по навигации открывает активный сезон `2026`. Для будущих событий календаря допустим лимит `2027`.
3. **Запоминание подвкладок:** Сайт сохраняет последнюю активную подвкладку каждого раздела в `localStorage` (`frontend/src/lib/navState.ts`). Навигационные ссылки шапки динамически ведут на сохраненную вкладку.
4. **Синхронизация параметров:** Хуки синхронизации query-параметров (`setSearchParams`) строго исключают циклические зависимости между URL path и query string.

### Dropdown Filters, Sex Filter Uniformity & Clean Breed Slugs

1. **Ленивый рендеринг меню:** Все выпадающие списки (`ModernDropdown`, `BreedSearchDropdown`, селекторы годов и классов) обязаны использовать отложенный рендеринг (`renderMenu` или флаг открытия `isOpen`), предотвращая создание тяжелых скрытых DOM-деревьев до клика.
2. **Единообразие фильтра по полу:** Пункт сброса пола во всех тулбарах строго именуется кратким словом **«Все»** (вместо «Любой пол», вызывавшего нежелательный перенос строки на мобильных экранах 375px).
3. **Чистые латинские слаги:** В URL-параметрах и внутренних ссылках породы кодируются исключительно стабильными латинскими слагами (`whippet`, `borzoi`), а не кириллицей.
4. **Без технических суффиксов:** В названиях пород категорически запрещены искусственные технические суффиксы в скобках вроде `(тип не указан)`. Названия выводятся строго в каноническом виде.

### Dog Profile Header, Action Buttons & Stable Fallbacks Invariant

1. **Расположение кнопок действий:** В шапке профиля собаки (`DogProfileHeader.tsx`) кнопки действий («В избранное», «Отслеживать») располагаются строго слева под метаданными (кличками, полом, ссылкой на родословную). Правый верхний угол зарезервирован под фото или породный силуэт.
2. **Стабильные фолбэки (Zero Re-render Thrashing):** В хуках данных профиля собаки (`useDogProfileData.ts`) при отсутствии данных запрещено использовать литералы пустых массивов `[]` как дефолтные значения пропсов (это нарушает равенство ссылок и вызывает бесконечный ререндер). Используются статически мемоизированные константы `EMPTY_ARRAY`.
3. **Формат пола собаки:** Компоненты пола (`DogSexIcon.tsx`, бейджи) обязаны поддерживать оба формата хранения: русские слова («Кобель» / «Сука») и символы (`M` / `F`). Значок пола рендерится через тонкий SVG без эмодзи.
4. **Контраст наград и мест:** В мобильных карточках протоколов 1 место выделяется теплым золотисто-янтарным бейджем, 2 место — серебристо-песочным, 3 место — бронзовым, без блеклых серых фонов.

### Typography Hierarchy, Clean Info Pages, Skeletons & Stable Scrollbar

1. **Шрифтовая система:**
   - **Inter (`font-sans`):** Таблицы, навигация, кнопки, бейджи, списки.
   - **Vollkorn (`font-serif`):** Крупные заголовки `h1`/`h2`, клички собак, логотип бренда.
   - **JetBrains Mono (`font-mono`):** Баллы, секунды, скорости, номера забегов.
2. **Регистр текста:** Строго `Sentence case`. Сплошной `UPPERCASE` запрещен для кличек собак, судей, турниров и длинных заголовков. Допускается только для мини-бейджей (`text-[10px] tracking-wider uppercase`).
3. **Чистота страниц «О проекте» и «Справка»:** Запрещены лишние декоративные бейджи над `h1`. Текст описаний оформляется единым кеглем `text-sm leading-relaxed text-charcoal-700` без искусственного выцветания последующих абзацев. Контактные карточки имеют строго 2 строки (категория + значение).
4. **Скелетоны-близнецы и скроллбар:** Скелетоны загрузки (`SeasonTopSectionSkeleton`) на 100% повторяют размеры и отступы реальных карточек, обеспечивая нулевой CLS. На корневом контейнере активно свойство `scrollbar-gutter: stable`, предотвращающее горизонтальный скачок верстки при переходе между страницами.

### Header Navigation, Underline Animation & Mobile Header Buttons

1. **Адаптивность логотипа шапки:**
   - Экраны $\ge 1280px$ (FHD, 2K, 4K): Полный горизонтальный логотип `/assets/brand/logo.svg` (`h-[52px]` до `h-[58px]`).
   - Экраны $768px - 1279px$ (планшеты, ноутбуки): Компактный бренд-медальон `/assets/brand/logo-badge.svg` (`h-[46px]`), дающий чистый зазор >100px до абсолютно центрированных пунктов меню (`absolute left-1/2 -translate-x-1/2`).
   - Экраны $< 768px$ (смартфоны): В `NavMobile` логотип `h-9 sm:h-10`.
2. **Анимация подчеркивания табов:** Активная вкладка навигации имеет плавную полоску `absolute bottom-0 left-0 w-full h-0.5 origin-left bg-camel-600 transition-transform duration-300`. Все вкладки шапки имеют одинаковую высоту и вертикальные отступы `py-2`.
3. **Круглые кнопки мобильной шапки:** Кнопка «Избранное» оформляется круглой стеклянной пилюлей `w-10 h-10 rounded-full`, а вкладка «Меню» — компактной плашкой `px-3 h-10 rounded-full`.
4. **Отложенный предзагрузчик (Heavy Tab Prefetch Deferral):** Предзагрузка тяжелых данных неактивных табов откладывается до наступления `requestIdleCallback` (или наведения курсора `onMouseEnter`), исключая просадки FPS при первичной загрузке страницы.

### Placement Medal Badges, Compact Event Header & Error Fallback

1. **Синхронизация медалей и бейджей:** Бейджи призовых мест на всех страницах (протоколы соревнований, выставки, профили собак) используют синхронизированную палитру: 1 место — золотистый `amber-700` на `amber-50`, 2 место — `stone-600` на `stone-100`, 3 место — `amber-800` на `amber-100/60`.
2. **Компактная шапка события:** В карточках турниров серия («Кубок Золотого Кольца», «Кубок Зайца») выводится компактным бейджем над названием, дата и статус выравниваются в единую строку.
3. **Экран ошибки (Error Boundary Fallback):** Компонент падения интерфейса оформляется в благородной стилистике Old Money: иконка `AlertTriangle` в янтарном круге, заголовок Vollkorn, кнопка «Обновить страницу» в стиле Physical Glass с touch target $\ge 44\text{px}$.

### Unslop & Anti-Slop Interface Polish Standard

В интерфейсе исключены любые признаки небрежного AI-кодинга («slop»):
1. Никаких пурпурных градиентов (`from-purple-500 to-indigo-600`), фоновых цветных пятен (`blob`), неоновых рамок или размытых свечений (`glow`).
2. Никаких бейджей с искрами («New ✨», «AI-powered», «Smart AI»).
3. Никаких пульсирующих индикаторов (`animate-pulse`) на статических элементах.
4. Отступы и паддинги выстроены по строгой 4px/8px модульной сетке Tailwind (`p-2`, `p-4`, `p-6`).

- Запрещено использовать div с onClick без доступных клавиатурных ролей и семантики.
