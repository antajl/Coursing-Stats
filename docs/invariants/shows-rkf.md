# Shows & RKF Exhibition Invariants

> Правила выставок РКФ: 56k статических протоколов, парсинг PDF, Главный ринг, связывание результатов и ранги

## Invariants & Architectural Rules

### Dog Profile Progressive Loading & Lightweight Competition-Show Linkage Invariant

1) Прогрессивная загрузка профиля собаки (`DogProfile/index.tsx`): если спортивная собака (`data.dog`) успешно загружена из CDN-пака, страница рендерится немедленно без блокировки интерфейса скелетоном `LoadingCard`. Поиск выставочных данных (`data.showsLoading`) выполняется асинхронно в фоне. Блокирующий экран ожидания допустим строго для профилей чисто выставочных собак (`!data.dog && data.showsLoading`), предотвращая ложные 404; 2) Микро-индекс связей `competition-links.json`: связи спортивных ID с выставочными собаками (`competition_dog_id -> show_dog_id`) выделены в отдельный компактный индекс `data/v1/shows/indexes/competition-links.json` (~24 КБ, 1195 связей). При резолве выставочной карточки по `competitionId` поиск выполняется строго через этот микро-индекс. Для чисто спортивных собак (без выставочной привязки) тяжелый поиск по 16 шардам реестра кличек `show-dog-lookup/` (186 МБ) строго запрещен; 3) Запрет сжатия JSON на лету в dev-сервере (`frontend/vite.config.ts`): в локальном dev-сервере раздача статических JSON из `data/v1/` выполняется прямым потоком `fs.createReadStream(filePath).pipe(res)`. Динамическое сжатие `zlib.createGzip({ level: 6 })` на лету в одном потоке Node.js строго запрещено: оно блокирует event loop dev-сервера на 3.5+ секунды при запросах браузера с `Accept-Encoding: gzip`; 4) В `ranking.ts` функции поиска выставочных карточек и all-time рангов обязаны кэшировать промисы в памяти сессии (`showDogLookupCache`, `showAllTimeRanksCache`), исключая повторные многомегабайтные сетевые запросы при переходах внутри SPA

### Sport Title 3-Tier Hierarchy

В `TitlesTab` запрещено дублировать одни и те же титулы в карточках и списках: награды структурируются строго в 3 хронологических уровня: 1) Базовый старт (Беговой допуск, CACL, CACIL); 2) Главные турниры года (ЧР РК, ПКР РК, ЧРКФ РК); 3) Накопительные звания (НЧ РК по 6 схемам, ГЧР РК, АЧР, C.I.C.)

### All-Time Top 100 Ranking & Slicing Invariant

В обоих рейтингах (выставки и курсинг/бега борзых) при выборе «Все года» без текстового поискового запроса отображение строго ограничивается **Топ-100** собаками (как в общем рейтинге без породы, так и внутри выбранной породы). При текстовом поиске по кличке фильтрация выполняется по всей базе. Для выставок полный исторический монолит (>220 МБ) запрещён к публикации на CDN: все года обслуживаются компактным файлом `shows/indexes/dog-ranking-all-time.json` (~17.6 МБ, ~2.2 МБ gzip), содержащим объединённый срез топ-100 общего зачёта и топ-100 по каждой породе с очками (`rank_score > 0`). Для первого экрана генерируется `dog-ranking-all-time-page0.json` (топ-100 общего зачёта, ~32 КБ). Пайплайн автообновления: функция `buildAllTimeTopRanking()` встроена в `build-show-indexes-by-year.ts` и `build-all-data.ts` — новые протоколы обновляют индекс всех времён автоматически

### RKF Exhibition Ingestion & Single-Date Freshness Invariant

1) Сайт в проде работает исключительно на статическом JSON с Яндекс S3 CDN (`/data/v1/`). Локальная SQLite база `data/local/exhibitions-rkf-archive.sqlite` (~224 МБ) исключена из git: автоматические cron-воркфлоу GitHub Actions, пытающиеся обратиться к локальному SQLite в облаке, строго запрещены (`.github/workflows/update-rkf-shows.yml` удалён). Синхронизация протоколов РКФ выполняется локально через `monitor-new-rkf-protocols.ts` с нормализацией оценок (`отлич` → `ОТЛ`, `о.перс` → `ОП`, `малоперсп` → `НЕПЕРСП`, `дисквал` → `ДИСКВ`, `уд` → `УДОВЛ`, `хор` → `ХОР`) и восстановлением обрывков пород по контексту ринга (`ИТАЛЬЯНСКИЙ`, `АНГЛИЙСКИЙ`, `БРЮССЕЛЬСКИЙ`, `БОРОДАТЫЙ`, `БЕРНСКИЙ`, `АЛЯСКИНСКИЙ`, `СИБИРСКИЙ`, `МОСКОВСКАЯ`, `ЧЕХОСЛОВАЦКАЯ`, `ЮЖНОАФРИКАНСКИЙ`, `НОРМАНДСКИЙ`, `АВСТРАЛИЙСКИЙ`, `НЕМЕЦКИЙ`, `ГОНЧАЯ`); 2) Дедупликация и профили: `enrich-show-dog-details.ts` сопоставляет собак протокола с существующей базой (715 000+ собак) по кличке, канонической породе и транслитерации RU↔EN. Если собака уже есть в базе, создаются указатели `alias_to` без дублирования профилей; новый профиль создаётся строго при отсутствии собаки в базе. Все файлы рейтингов (`dog-ranking-*.json`) содержат 100% канонические ID (0 алиасов); 3) В панели календаря (`ShowCalendarHint.tsx`, `ShowCalendarToolbar.tsx`) двойные даты («календарь отдельно, протоколы отдельно») запрещены. Кнопка тулбара оформляется единым шрифтом `Об архиве · 16 нояб.` (`text-xs font-semibold`), а в карточке статус объясняется в две сбалансированные строки: «В базу внесены все данные РКФ, / опубликованные к 16 ноября 2026 г.», устраняя путаницу между датой сверки и задержкой публикации протоколов самим РКФ; 4) В модальной карточке архива избыточный заголовок «Архив выставок РКФ» упразднен

### Show Dog Protocol Linking & Alias Completeness Invariant

В протоколах выставок РКФ за все года клички собак в таблицах породных рингов и Главного ринга (BIG/BIS) могут содержать секретарские опечатки в согласных (`ОБЕССИОН` ↔ `ОБСЕССИОН`), технические суффиксы пола/разновидности (`(M)`, `(T)`, `(К)`, `(С)`), номера родословных/клейм в поле клички (`RKF \d+`, `РКФ \d+`), двуязычные записи со слэшем (`RU/EN`) или усечённые приставки питомника в Главном ринге. Для гарантированного исключения 404: 1) В клиенте (`ranking.ts`: `resolveShowDogDetail`) функция `cleanShowDogNameVariants` выполняет предварительную очистку суффиксов, сплит по слэшу и нечёткое сопоставление через `show-dog-lookup`; 2) В офлайн-пайплайне (`enrich-show-dog-details.ts`) выполняется сканирование всех выставок SQLite с автоматическим связыванием собак Главного ринга с результатами выставки по номеру по каталогу или префиксу имени, генерируя прямые алиасы `alias_to` в `dog-details/` (строго глубина <= 1, 0 висячих алиасов); 3) Все файлы рейтингов `dog-ranking-*.json` сохраняют 100% канонические ID (строго 0 алиасов), что гарантируется тестом `show-dog-alias-resolution.test.ts`

### Dog Silhouette 2D Vector Generation Standard

Все силуэты пород собак (для шапок профилей `/dog/:id`, карточек выставок и витрин) генерируются строго по эталонному стандарту 2D-вектора: 1) Четыре лапы на земле: обе передние и обе задние конечности заземлены на базовой линии горизонта ($y = 170.0$), разделены 1.5px анатомическим зазором отрицательного пространства (negative space), без обрезанных или скрытых конечностей; 2) Бесполая атлетическая линия низа: контур подрыва живота и паха плавный, непрерывный, без препуциальных мешков, семенников и генитальных выступов; 3) Чистый бесшовный белый фон (#FFFFFF): без теней на полу, без градиентов, размытия или контактных клякс под лапами; 4) Оптическое масштабирование: привязка к сетке 200×200 с ограничением максимальной ширины $max\_w = 176.0\text{ px}$ (боковые отступы $\ge 12\text{ px}$) и иерархией высот от 65 px (той-породы) до 145 px (волкодавы/доги); 5) Сглаживание Чайкина: контуры растра сглаживаются в вектор (1 итерация, epsilon=0.5) без ступенчатых пиксельных зазубрин; 6) Запрет эмодзи в метаданных и коде

Вместо них для спортивного зачёта используются формулировки «результаты забегов, титулы и статистика», а для выставочного — «выставки РКФ, титулы и результаты рингов»

### Show History Chronological Sorting Invariant

В истории выставочных выступлений собак (`ShowHistoryEntry.date`, `ShowsColumn.tsx`, `dog-details/*.json`, `build-show-indexes*.ts`, `show-dog-dedupe.ts`) даты выставок РКФ хранятся в формате `DD.MM.YYYY`. Строго запрещено сортировать их лексикографически напрямую через `localeCompare` или строковые операторы (что приводило к сортировке по дню месяца 31→01 и хаотичному разбросу месяцев и лет). Для всех сравнений и отображения обязательна нормализация в ISO `YYYY-MM-DD` через утилиту `toShowDateIso` и использование компаратора `compareShowHistoryDesc` / `sortShowHistory` из `backend/lib/show-dates.ts`. Во фронтенде в `ShowsColumn.tsx` массив истории обязан дополнительно мемоизироваться и сортироваться клиентом перед срезом `visible` для защиты от старого кэша

### Dog Profile Stable Fallbacks & Memoization Invariant

В профиле собаки (`DogProfile`, `useDogProfileData.ts`, `useDogProfileRanks.ts`) для собак чисто выставочного домена (`show_dog_id`, `isShowOnlyProfileId`) и отсутствующих спортивных результатов запрещено использовать литералы `[]` в качестве дефолтных значений массивов `events`, `speedRecords`, `coursingRecords`, `breedRecords`, `breedCoursingRecords`: обязателен синглтон `EMPTY_ARRAY: never[] = []` для сохранения ссылочной идентичности (`[] === []`). Хук `useDogProfileRanks` обязан сравнивать новые ранги с предыдущими (`areRanksEqual`) перед вызовом `setAsyncRanks` и использовать примитивные ключи в массиве зависимостей `useEffect` (`dog?.id`, `showDog?.id`, `showDog?.rank`, `events.length` и т.д.), полностью исключая циклы бесконечных фоновых ре-рендеров. В `ShowsColumn.tsx` вычисления `bestExhibitionId` и `bestGrade` обязаны мемоизироваться (`useMemo`), предотвращая повторный парсинг наград при наличии сотен выставок

### Exhibition Protocol S3 CDN & CI Protection Invariant

Все 56 225 протоколов выставок (2019–2026) отдаются в gzip из Яндекс S3 CDN (`/data/v1/shows/protocols/{id}.json`). В `deploy.yml` команда `aws s3 sync data/v1/ ... --delete` обязана содержать `--exclude "shows/protocols/*"`, защищая протоколы от удаления при вызове full sync в GitHub Actions. Список доступных протоколов для судей и sitemap генерируется из SQLite архива (`available-exhibitions.json`), а в экране ошибки `ShowExhibitionDetail.tsx` выводится прямая ссылка на `rkf.online` при несуществующем ID

### Sport-Show Dog Identity Alias Resolution & Zero 404 Fallback Invariant

1) Дедупликация и алиасы выставочных собак: `enrich-show-dog-details.ts` вычисляет прямые указатели `alias_to` для связанных спортивных собак на основе `stableShowProfileId` всех транслитерационных вариантов имен и пород, валидирует и уплощает цепочки алиасов (глубина строго $\le 1$, устраняя транзитивные ссылки `A -> B -> C`), а висячие ссылки на несуществующие профили автоматически удаляются; 2) Защита от 404 в профиле собаки: во фронтенде (`useDogProfileData.ts`, `DogProfile/index.tsx`) при переходе по ссылке чисто выставочного формата (`isShowOnlyProfileId`), если профиль не найден в выставочной базе, но передан параметр запроса `queryName`, выполняется фоновый поиск по `dogs-index.json`. При обнаружении совпадения в спортивной базе маршрут автоматически редиректит на канонический спортивный профиль `/dog/:id/`, исключая экраны «Собака не найдена»

### RKF Breed Varieties & Dual-Name Display Invariant

В официальном реестре пород РКФ (`rkf-breeds.json`) для пород с разновидностями (пудели, таксы, бельгийские овчарки) поле `baseBreed` отделено от `variety`. Функция `displayBreed(breed)` возвращает `{ primary: baseBreed, variety, full: primary + ' ' + variety }`, гарантируя объединение в единую породу в фильтрах каталога и аккуратный рендеринг разновидности (`text-charcoal-400 font-normal`) в карточках собак (`ShowDogCard.tsx`, `DogCardParts.tsx`, `DogProfileHeader.tsx`) и выпадающем списке `BreedSearchDropdown.tsx`. В карточках выставок при наличии клички на кириллице и латинице вторичное имя выводится ненавязчиво через слэш (`/ {secondary}`), предотвращая обрезку и сохраняя визуальную эстетику Old Money

### Toolbar Events Stats Non-Duplication

### Mobile Competition Protocol & Seamless Group Density

На мобильных экранах (`< 640px`) результаты состязаний (`EventResults`) обязаны рендериться через `MobileCardsProtocolView.tsx` (вместо горизонтального скролла широкой таблицы). 1) Внутри группы породы: заголовок группы (`bg-camel-100/80 border-b border-camel-200/90`) и карточки собак смыкаются абсолютно бесшовно (`divide-y divide-old-money-100/70`, ноль зазоров). 2) Между группами пород: строгий аккуратный разделительный пробел `space-y-3` (12px), визуально обособляющий блоки пород. 3) Единый горизонтальный ряд забегов: плашки забегов/заездов ВСЕГДА рендерятся в один горизонтальный ряд колонок (`grid-cols-2` для 2 забегов, `grid-cols-3` для 3 заездов). Запрещено переламывать 3 заезда в вертикальные строки друг под другом при сохранении колонок у 2 забегов. 4) Инвариант курсинга: в курсинге и БЗМП всегда строго 2 забега (ветеринарный регламент РКФ/FCI), 3 заезда бывают только в рейсинге (квалификация, полуфинал, финал)

В мобильной версии протокола состязаний (`MobileCardsProtocolView.tsx`) в подвале карточки участника (`Награды:`) обязаны отображаться все полученные собакой сертификаты и титулы (включая `СС` / `ЮСС` / `ВСС` высшей квалификации, `CACMB` / `RegCACMB`, `CACL` / `RegCACL`, `ЧРКФ`, `ЧР` и лиги) в обособленной плашке с рамкой (`border border-old-money-200/70 bg-white/85 rounded-lg`). ### Breed Hub Canonical Slugs & Variety Aliasing

При наличии внутри породы разновидностей по росту или шерсти (таксы: стандартная/мини/кроличья, поденко, шнауцеры, пудели) основной породный хаб использует канонический международный слаг (`dachshund`), а специализированные наименования и синонимы регистрируются в `aliases` (`miniature-dachshund`, `taksa`). Функция `matchesBreedFilter` обязана сопоставлять базовый канонический ключ породы («ТАКСА») со всеми ее спецификациями в базе состязаний и выставок

## Domain Forbidden Rules

- Включать оценки классов бэби и щенков («очень перспективный», «перспективный») в знаменатель процента «отлично» судей выставок (искусственно занижает судейскую строгость на 10–15 п.п., так как щенки по правилам РКФ не могут получать «отлично»)
- Связывать или объединять собак разных пород между спортом и выставками по совпадению клички (`linkShowDogsByUniqueName`, `collapseShowDogsByExactName` без валидации породы)
- Leaving raw downloaded PDF reports in data/local/rkf-reports/ after parsing into SQLite (raw PDFs are ephemeral and must be deleted after compression to avoid disk bloat)
- Discarding or skipping Main Ring tables when embedded inside single certificate PDFs (the parser must support detecting «ВЕДОМОСТЬ ГЛАВНОГО РИНГА» and extracting placements alongside catalog results)
- Сортировать списки пород в фильтрах выставок в произвольном порядке: породы обязаны выводиться по убыванию количества собак (от самых массовых к редким) с аккуратным алфавитным вторичным ключом
- Отбрасывать 2-й забег или выставлять статус `finished`, если собака сошла с трассы или была снята во 2-м круге (второй забег обязан фиксироваться с `disqualified: true` и причиной схода/снятия)
- Запрашивать неиспользуемые на странице наборы данных (календари турниров, списки выставок) в хуках первого экрана (`useHomeData`)
- Оставлять неразрешённые алиас-ID в файлах рейтингов выставок (`dog-ranking-*.json`): все файлы рейтингов обязаны содержать исключительно 100% канонические ID собак; ссылки-алиасы допустимы только в `dog-details/`
- Использовать иконки локации/пинов перед строкой адреса, если они сдвигают её относительно названия организации (адрес и клуб в карточках соревнований и выставок обязаны начинаться строго по единой вертикальной оси с нулевым сдвигом)
