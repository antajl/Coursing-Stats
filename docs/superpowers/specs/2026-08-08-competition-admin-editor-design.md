# Design: Local Competition Admin Editor

**Date:** 2026-08-08  
**Status:** implemented MVP (2026-08-08); calendar link via `sync-archive-comps-to-calendar`  
**Scope:** competitions domain only (not shows, not Donino)

## Problem

Нужно вручную проверить каждое соревнование по внешней информации (в т.ч. с бумажки) и быстро править данные у нас локально, без правок JSON через агента и без перепарса с procoursing.

## Goals

- Найти событие на сайте и открыть удобный редактор.
- Править метаданные события и таблицу результатов (add/delete строк; детальные очки — часть того же дизайна, см. фазы ниже).
- Сохранять **по одному событию** сразу на диск.
- Отмечать событие как «проверено».
- При Save для этого события создавать/привязывать собак без `dog_id`.
- На прод уезжает только то, что в git после обычного пайплайна.

## Non-goals

- Перепарс / импорт HTML с procoursing в этом UI.
- Shows / Донино.
- Кнопка `build-all-data` в UI (делается в консоли).
- Публичный редактор на проде.
- Автоматический merge «похожих» собак сложнее, чем match по нормализованной кличке+породе.

## Approach

Отдельная admin-страница + DEV-кнопка с публичного протокола.

| Поверхность | Назначение |
|-------------|------------|
| `/event/:id` (DEV) | Кнопка «Редактировать» → admin |
| `/admin` | Список событий + галочка «проверено» + создание нового события |
| `/admin/event/:id` | Редактор шапки + таблицы |
| Local API `:8787` | Чтение/запись `data/v1/` |
| Консоль | `yarn run build-all-data` перед продом / когда нужны свежие рейтинги |

## User flow

1. `yarn run dev`.
2. Найти событие как обычно на сайте (календарь / ссылка).
3. На `/event/:id` нажать «Редактировать» (только DEV) → `/admin/event/:id`.
4. Править шапку и/или строки результатов (можно с листочка).
5. **Сохранить** — файл события на диске обновлён; новые собаки для этого события созданы/привязаны.
6. Поставить «Проверено», сохранить ещё раз (или в том же Save).
7. Следующее событие.
8. Когда нужно обновить рейтинги/календарь на локальном сайте или перед пушем: `yarn run build-all-data`.
9. Коммит/пуш `data/v1/` → прод через обычный CI/CDN.

## UI

### `/admin`

- Список событий: год, дата, название, локация, статус «проверено».
- Фильтр по году (минимум).
- Клик по строке → редактор.

### `/admin/event/:id`

- **Шапка (editable):** дата начала/конца, title / rank_label, локация, клуб, судьи, ссылки (catalog/results), галочка «Проверено».
- **Таблица результатов:** собака (поиск существующих или свободный текст без id), breed_class, placement, total_score, status / status_reason, qualification / vc; раскрытие строки → детальные очки (`raw_scores_json`: heats/судьи) в зависимости от типа события.
- **Действия со строками:** добавить, удалить (с подтверждением).
- **Sticky Save:** активна при наличии изменений; пишет только текущее событие.

Публичный вид `/event/:id` не дублируем 1:1 — редактор плотнее и удобнее для ручной сверки.

## Data behavior on Save

1. Записать актуальные `event` + `results[]` в файл  
   `data/v1/competitions/{year}/{month}/{id}-….json`.
2. Для строк **этого** события без `dog_id`, но с именем/породой:
   - найти существующую собаку по нормализованному ключу (кличка + порода);
   - если нет — создать запись в `dogs/` и выдать новый id;
   - проставить `dog_id` и объект `dog` в строке результата.
3. **Не** запускать `build-all-data`.
4. **Не** менять placement / scores / status при создании собак — только identity fields.

### Verified flag

- Хранить в JSON события: `event.admin_verified_at` (`ISO string` | `null`).
- Публичный UI поле игнорирует.
- Список `/admin` показывает галочку по наличию `admin_verified_at`.

## Local API (behavior, not UI jargon)

Нужны операции local-only admin API:

- Список событий (для `/admin`).
- Загрузить документ события (event + results).
- **Сохранить документ события** одним запросом (предпочтительный путь Save из UI) + ensure-dogs для этого события.
- Поиск собак по строке (для привязки к существующим).

Существующие точечные endpoints (`PUT` event fields, CRUD result) можно оставить/переиспользовать внутри, но UX Save = один снимок документа.

Ограничение доступа: только local `:8787`, заголовок `X-Admin-Token` если задан `ADMIN_API_TOKEN`.

## After edits (console)

```bash
yarn run build-all-data
```

- Читает competitions/dogs как источник правды.
- Пересобирает indexes и календарь.
- **Не откатывает** ручные правки в файлах соревнований (не перепарсивает протоколы заново).

В DEV Vite отдаёт `/data/v1` прямо из репо: после Save и обновления `/event/:id` протокол показывает новые данные. Рейтинги/календарные агрегаты из `indexes/*` могут быть устаревшими до `build-all-data`.

## Error / edge cases

| Ситуация | Поведение |
|----------|-----------|
| Save упал | Файл не меняется; правки остаются на экране; можно повторить |
| Удаление строки | Confirm; после успешного Save удаление на диске |
| Две одинаковые кличка+порода | При Save без id привязка к одной существующей собаке (без автосоздания дубля) |
| Смена даты события | В файле сразу; в UI-календаре — после `build-all-data` |
| Прод | Нет admin UI / нет записи в `data/v1` с браузера |

## Phased delivery

1. **MVP:** `/admin` список + `/admin/event/:id` шапка + верхний уровень results + add/delete + verified + Save (файл + ensure-dogs) + DEV-кнопка с `/event/:id`.
2. **Детальные очки:** редактор heats/судей по типам coursing / BZMP / racing.
3. **Polish:** фильтры списка, keyboard UX, более явные сообщения о созданных собаках после Save.

## Out of design / later

- Разведение тёзок (две разные собаки с одной кличкой+породой) — отдельный tooling.
- Audit log / history undo.
- Batch Save нескольких событий.

## Success criteria

- Можно пройти событие end-to-end: открыть → поправить шапку и строки → Save → увидеть изменения в файле на диске.
- Новая собака без id после Save получает id и появляется в `dogs/`.
- Галочка «проверено» видна в `/admin`.
- На production-сборке нет UI записи.
- После `build-all-data` рейтинги/календарь согласованы с отредактированными файлами без потери ручных правок.
