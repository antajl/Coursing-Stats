# План аудита качества кода CoursingStats

## Обзор

Систематический аудит качества кода проекта CoursingStats для выявления архитектурных нарушений, дублирования, проблем безопасности и технического долга. Проект написан ИИ, требуется проверка чистоты кода.

## Цели аудита

1. **Архитектурная чистота** - соответствие трём доменам, CDN vs Turso
2. **Отсутствие дублирования** - код не должен повторяться
3. **Безопасность** - нет секретов, правильная валидация
4. **Тестирование** - покрытие критических путей
5. **Качество кода** - именование, организация, читаемость
6. **Документация** - актуальность AGENTS.md и docs/
7. **Производительность** - нет явных проблем
8. **Зависимости** - актуальность и безопасность

## Задачи аудита

### Фаза 1: Архитектурный аудит (КРИТИЧНО)

**Task 1: Проверка смешивания доменов**
- **Описание:** Проверить нет ли смешивания сущностей Competitions/Shows/Donino без необходимости
- **Критерии приёма:**
  - [ ] Нет функций которые работают с dog_id соревнований и show dogs одновременно без sport-show-linkage
  - [ ] Нет смешивания рейтингов спорта и выставок
  - [ ] Судьи соревнований и выставки разделены
- **Проверка:** `grep -r "dog_id.*show" backend/ frontend/` + ручной анализ
- **Файлы:** `backend/lib/`, `frontend/src/`
- **Размер:** S

**Task 2: Проверка CDN vs Turso violations**
- **Описание:** Убедиться что Turso используется только для протоколов выставок, не для ranking/calendar
- **Критерии приёма:**
  - [ ] Нет кода который читает ranking из Turso
  - [ ] Нет кода который читает calendar из Turso
  - [ ] LC allowlist данные загружаются из CDN
- **Проверка:** `grep -r "turso\|libsql" backend/` + анализ использования
- **Файлы:** `backend/lib/`, `backend/scripts/`
- **Размер:** S

**Task 3: Проверка forbidden patterns**
- **Описание:** Проверить нет ли запрещённых паттернов из AGENTS.md
- **Критерии приёма:**
  - [ ] Нет кода который загружает все породы + архив 2015-2026 в UI
  - [ ] Нет кода который мержит medals и CS points
  - [ ] Нет кода который парсит Breed Archive PDF (только URL)
  - [ ] Нет кода который деплоит Worker в CI сайта
- **Проверка:** `grep -r "breeds.*2015\|medals.*points\|breed.*pdf" backend/ frontend/`
- **Файлы:** `backend/`, `frontend/`, `.github/workflows/`
- **Размер:** S

### Checkpoint: Архитектура
- [ ] Нет критических архитектурных нарушений
- [ ] Соответствует трём доменам
- [ ] CDN vs Turso разделение соблюдено

## Риски и mitigations

| Риск | Влияние | Mitigation |
|------|---------|------------|
| Архитектурные нарушения могут быть глубокими | High | Начать с архитектурного аудита, остальные задачи зависят от этого |
| Дублирование может быть повсеместным | Medium | Приоритизировать консолидацию critical дубликатов |
| Тесты могут отсутствовать в важных местах | High | Проверить coverage критических путей |
| Документация может устареть | Medium | Обновить документацию по мере находок |

## Стратегия выполнения

1. **Начать с архитектурного аудита** - это фундамент, все остальное зависит от этого
2. **Параллельно можно делать** аудит безопасности и дублирования (независимые)
3. **После архитектуры** - аудит качества кода и тестирования
4. **Завершить** - документацией и итоговым отчётом

## Приоритеты

**Critical (нужно исправить немедленно):**
- Архитектурные нарушения
- Проблемы безопасности
- Отсутствие тестов в критических местах

**High (стоит исправить):**
- Дублирование кода
- Проблемы качества кода
- Устаревшая документация

**Medium (можно отложить):**
- Проблемы производительности
- Минорные проблемы качества кода

**Low (косметические):**
- Стиль кода
- Минорные улучшения документации
